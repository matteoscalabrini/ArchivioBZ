# Search with a hidden layer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A search field beside the tabs that narrows the Library's list to two groups, precise and possible links, over a hidden layer of terms under every row, each hit naming its reason.

**Architecture:** The build writes one static file, `search.json`, holding for every row its line, its hidden terms, its text, its notes, its table's records and its read's paragraphs, plus three shared lists. In the browser a pure module (`web/search.js`) turns that file into an engine and answers a query with two ordered lists of hits and their reasons; a second pure module (`web/results.js`) turns hits into what the page shows; `web/library.js` only moves DOM nodes. The hidden terms are content: `find.json` beside each `entries.json`, checked by the build.

**Tech Stack:** Node 24 (ES modules, `node --test`), plain browser JavaScript, no new package.

**Spec:** `docs/superpowers/specs/2026-11-17-search-design.md`

## Review Focus

1. **Markup in what is typed** (`<b>`, `"`, `&`, `(`): it reaches the reason line, the status line, "Nothing found for …" and the address. Expected: shown as typed, never as markup; the address round-trips. Tests in Task 5; "Nothing found" set as text in Task 9.
2. **A search that is empty, only small words, only punctuation, or an open quotation mark** (`""`, `the`, `…`, `"heim ins`): no error; nothing typed shows every row; small words alone are searched as typed; an open quote runs to the end. Tests in Task 1.
3. **`search.json` missing or unreadable** (offline, a stale deployment): the Library still lists and filters; the status line says the search is not available. Test in Task 5 (`summary`), glue in Task 9.
4. **A search together with a keyword, a kind, open rows and a jump from "Sources"**: all narrow together; a row the search hides is shown when a jump asks for it, by clearing the search. Tests in Task 5 (`layout`), glue in Task 9.
5. **Typed words with punctuation inside** (`5.02`, `Lana-Meran`, `dell'Alto`, `12.7.1926`): the parts must stand together in that order; a row number finds its row first. Tests in Tasks 1 and 2.

## The index, `search.json` (used by Tasks 1–6)

```json
{
  "v": 1,
  "colours": { "red": ["red", "rosso", "rossa", "rot"] },
  "names": [["Bolzano", "Bozen"]],
  "glossary": [["eagle", "aquila", "Adler"], ["cable car", "funivia", "Seilbahn"]],
  "rows": [{
    "no": "1.05",
    "line": ["1.05", "Municipio di Bolzano – Cittadini! / Bürger!", "Poster", "19 May 1925", "Posters", "Language"],
    "on": ["die Königin des Hochetsch"], "shows": ["a bilingual public notice"], "colours": ["red"], "names": [],
    "text": ["A paragraph of the row's text."], "facts": ["A fact, its source tags taken out."],
    "table": ["cell · cell · cell"], "read": ["One paragraph of the read."]
  }]
}
```

`rows` are in the library's order. A list that is empty is left out. Sources and their strength: `line` 1; `on`, `shows`, `colours`, `names` 2; `text`, `facts` 3; `table`, `read` 4.

### Task 1: Folding and the query

**Files:**
- Create: `library/web/search.js`, `library/test/search-index.mjs`
- Test: `library/test/search.test.mjs`

**Interfaces:**
- Produces:
  - `fold(text: string): string` lower case, accents off, `ß` to `ss`.
  - `words(text: string): Array<{ w: string, from: number, to: number }>` the folded words of `text` (runs of letters and digits) with their place in it, `to` exclusive.
  - `parseQuery(text: string, lists: { colours, names, glossary }): Term[]`, where `Term = { typed: string, parts: string[], exact: boolean, alts: Array<{ parts: string[], road: '' | 'glossary', says: string }>, colour: string | null }`. `typed` is the words as typed; `parts` its folded words; `exact` is true for a quoted phrase, a name and a colour (no loose roads); `alts` are the other ways it may stand (the first is the term itself); `says` is the alternative in its own spelling.

Rules the tests pin:
- Text between `"` is one term, `exact`. An open `"` runs to the end.
- Outside quotes, text is cut at white space; a chunk with punctuation inside (`5.02`, `Lana-Meran`, `dell'Alto`) is one term whose parts must stand together.
- A run of chunks that spells a name of `lists.names` is one term, `exact`, with every name of that set as an alternative. The longest run wins.
- A chunk that is a colour name is one term, `exact`, `colour` set to the colour's id, with every name of that colour as an alternative.
- A chunk, or run of chunks, that is an item of `lists.glossary` gets the set's other items as alternatives with `road: 'glossary'`. It is not `exact`.
- A part with `ae`, `oe` or `ue` gets an alternative with those written `a`, `o`, `u` (`fuehrer` also stands as `fuhrer`).
- Small words are dropped: `the a an of in on and with for to di del della dei delle il lo la le i e da der die das und von des den dem im`. If nothing else was typed, they are kept.

  assert.deepEqual(parseQuery('Königin des Hochetsch', INDEX).map((t) => t.parts), [['konigin'], ['hochetsch']]);
  assert.deepEqual(parseQuery('the', INDEX).map((t) => t.parts), [['the']]);
});
test('parseQuery: nothing typed, only punctuation, markup', () => {

### Task 2: Precise hits

**Files:**
- Modify: `library/web/search.js`
- Test: `library/test/search.test.mjs`

**Interfaces:**
- Consumes: `parseQuery`, `words`, `fold`.
- Produces:
  - `prepare(index): Engine` built once from `search.json`. Opaque; holds `index.rows` in order.
  - `search(engine: Engine, text: string): { terms: number, precise: Hit[], possible: Hit[] }`, `Hit = { no: string, reasons: Reason[] }`. Task 2 fills `precise` and leaves `possible` and `reasons` empty.

Rules:
- A term stands in a source when the parts of one of its alternatives with `road: ''` stand there together, in order. A colour term also stands in a row whose `colours` hold its id.
- A row is precise when every term stands in its sources of strength 1 to 3 taken together, or every term stands in one string of its `table`, or every term in one string of its `read`.
- Its strength is the largest, over the terms, of the smallest strength at which each stands; 4 when it is precise only through a table record or a read paragraph.
- Order: strength, then the rows' order in the index.

### Task 3: Possible links

**Files:**
- Modify: `library/web/search.js`
- Test: `library/test/search.test.mjs`

**Interfaces:**
- Produces: `search(...).possible`, ordered; `family(a: string, b: string): boolean` and `near(typed: string, word: string): boolean`, exported for the tests.

Rules:
- `family(a, b)`: the words differ, share their first `p` letters with `p >= 4`, each has at most 3 letters after them, `p / max(length) >= 0.6`, and neither holds a digit.
- `near(typed, word)`: neither holds a digit, `typed` has 5 letters or more, and the edit distance is at most 1 when `typed` has 5 to 7 letters, at most 2 when it has 8 or more.
- A term that is not `exact` may reach a row by a loose road, ranked: 1 word family (a word of the row is `family` to the typed word); 2 glossary (an alternative with `road: 'glossary'` stands, or a word `family` to a one-word alternative does; and a typed word `family` to a glossary item takes that item's set); 3 near spelling.
- A term reaches a row at rank 0 when it stands in the row at all, in any source.
- A row is a possible link when it is not precise and at least half of the terms (rounded up) reach it.
- Order: more terms reached first; then the worst rank among them (0, 1, 2, 3); then the strength, worked out as in Task 2 over the terms reached; then the rows' order.

### Task 4: Reasons

**Files:**
- Modify: `library/web/search.js`
- Test: `library/test/search.test.mjs`

**Interfaces:**
- Produces: `Hit.reasons: Reason[]`, `Reason = { label: string, text: string, marks: Array<[from: number, to: number]>, road: string }`, at most 3 for a hit.

Rules:
- One reason for each source string a term was found in, the terms found in one string sharing it (their marks together, in order). Where a term stands in several sources the strongest is used; within strength 2 the order is `on`, `shows`, `colours`, `names`; within 3, `text` before `facts`.
- No reason for a term that stands in `line` as typed.
- `label` and `text` by source:

| Source | `label` | `text` |
|---|---|---|
| `line`, by a loose road | `''` | the word that stands, as it stands |
| `on` | `on it` | the whole phrase |
| `shows` | `shows` | the whole phrase |
| `colours` | `colour` | the colour's id |
| `names` | `also called` | the whole name |
| any source, a name other than the typed one stands | `also called` | the typed name, in the list's spelling; marks the whole |
| `text` | `in the description` | a cut |
| `facts` | `in the notes` | the word or words that stand, as they stand, nothing else |
| `table` | `in its table` | a cut |
| `read` | `in the long read` | a cut |

- A cut is the source string when it has 90 characters or fewer; otherwise 90 characters around the first mark, cut at spaces, with `…` at a cut end. `marks` are places in `text`.
- `road`: `''`; `same word family`; `<typed> = <glossary item>` (`aquila = eagle`); `near “<typed>”`, the typed word as typed.
